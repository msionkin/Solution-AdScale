# Архитектура потоковой обработки событий с помощью Kafka

Цель - развязать критичный путь (ставки, показы) от write-нагрузки статистики/аналитики. События не теряются и не блокируют производителя. Это путь к событийно-ориентированной архитектуре через год.

## Топики Kafka

| Топик              | Производитель    | Потребители                                 | Назначение                                                                                                                                        |
|--------------------|------------------|---------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| `auction-events`   | Сервис ставок    | Статистика, Аналитика, Delivery             | Результат аукциона (`AuctionEvent`) публикуется асинхронно. Delivery — отложенная генерация разметки; Статистика/Аналитика — исторические данные. |
| `ad-events`        | Delivery Service | Статистика, Аналитика                       | События показов/кликов. Delivery не делает синхронный вызов в Статистику, а публикует событие и не ждёт записи.                                   |
| `campaign-changes` | Сервис кампаний  | Сервис ставок (обновление Redis read-model) | Инвалидация/обновление кэша кампаний/бюджетов/ставок. Обеспечивает CQRS.                                                                          |

## Схема событий

Для внутренних частых событий таких как `auction-events`, `ad-events` необходимо использовать Avro. Avro (по сравнению с JSON) предлагает компактную бинарную сериализацию, меньше накладных расходов при высоком RPS, и этот формат согласуется с выбором protobuf/gRPC.

## Группы потребителей (consumer groups)

Один топик независимо читают разные группы:

- `statistics` — batch запись событий в PostgreSQL статистики.
- `analytics` — наполнение аналитического/отчётного контура.
- `delivery` — генерация HTML/JS-разметки по `auction-events`.
- `bidding-cache` — применение `campaign-changes` к Redis read-model.

См. диаграмму `diagrams/event-streaming.puml`.
