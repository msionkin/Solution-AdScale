# API Gateway для DSP-интеграции

API Gateway — единственная точка входа для трафика от DSP-партнёра, стоит на границе перед Ad Server (см. `interaction.md`). Используемая технология — NGINX + Lua: поддерживает HTTPS, по которому идут запросы от DSP-партнёра, высокая производительность и гибкость за счёт Lua-скриптов для кастомной логики (аутентификация, rate limiting, circuit breaker).

Приём `POST /v1/openrtb2/bid`, маршрутизация на отдельный пул инстансов Ad Server, обслуживающих только внешний DSP-трафик, которые не пересекается с внутренним трафиком. 

Ограничение частоты запросов. Глобальный лимит на upstream — защита Ad Server/Bidding Service от перегрузки суммарным внешним трафиком. При превышении выдавать ошибку `429 Too Many Requests` с `Retry-After`.

Соединение DSP-партнёра с API Gateway происходит по HTTPS. Аутентификация DSP-партнёра — по API-ключу в заголовке запроса.

В открытом NGINX нет встроенного circuit breaker — паттерн нужно реализовать самостоятельно через Lua-скрипты (подсчёт ошибок/таймаутов от Ad Server) либо перейти на NGINX Plus, где есть встроенные active/passive health checks upstream-сервера, которые можно использовать как основу circuit breaker. При превышении порога ошибок — circuit breaker переходит в состояние open: запросы в упавший upstream не идут, партнёру сразу возвращается `no-bid` ответ. Периодически происходит проверка (состояние half-open) для автоматического восстановления трафика.

Необходимо реализовать метрики p50/p95/p99 latency и error rate.
