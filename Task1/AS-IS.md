# AS-IS: Анализ текущей архитектуры AdScale

Анализ построен по диаграмме [C4 Container (AS-IS)](diagrams/AS-IS.puml): монолит из 7 компонентов на общем процессе, единый PostgreSQL, внешние DSP-партнёры и платёжный шлюз.

## Ключевые показатели

- Нагрузка: **15 000 RPS** (пик), запаса по производительности нет.
- Latency: **P95 110–120 мс** при требовании **≤ 100 мс** — SLA нарушается.
- Периодические деградации в часы пик.
- Нет кэширования, асинхронных очередей, контейнеризации; деплой вручную.

## Узкие места (bottlenecks)

| Компонент              | Проблема                                                      | Влияние                                          |
|------------------------|---------------------------------------------------------------|--------------------------------------------------|
| **Auction Engine**     | Синхронные вызовы к БД в hot path (критический путь аукциона) | Прямой рост latency, превышение SLA              |
| **Statistics Service** | Прямая запись показов/кликов в БД без буферизации             | Конкуренция за ресурсы БД, деградация записи     |
| **Analytics Service**  | Тяжёлые OLAP-запросы напрямую на production-БД                | Блокировки, рост latency транзакционных операций |

## Точки отказа 

- **PostgreSQL — единственная инстанция**: нет HA, нет read-replica. Отказ БД = отказ всей системы.
- **Монолит с общим процессом**: сбой или пиковая нагрузка на одном компоненте влияет на все остальные (нет изоляции отказов).

## Проблемы масштабирования

- Единый деплой — нельзя масштабировать компоненты независимо, хотя у них разные SLA (аукцион ≤100 мс критично, аналитика — нет).
- OLTP (аукцион, финансы) и OLAP (аналитика) конкурируют за одну БД.
- Отсутствие кэша и очередей — вся нагрузка идет синхронно в одну БД.
- Ручной деплой без контейнеризации ограничивает горизонтальное масштабирование.

## Влияние на время отклика

Критический путь `Ad Server → Auction Engine → Delivery` синхронно ходит в перегруженный PostgreSQL, который одновременно обслуживает запись статистики и тяжёлую аналитику. Это объясняет превышение P95 (110–120 мс против ≤100 мс).
